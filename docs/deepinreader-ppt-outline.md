## 2. 项目背景与痛点

### 学术论文阅读痛点

- 论文篇幅长、信息密度高，阅读成本大。
- 方法、实验、结论分散，快速理解困难。
- 普通摘要工具只能压缩文本，缺少结构化理解。
- 通用聊天机器人容易脱离原文，回答缺乏证据来源。
- 多篇论文对比耗时，难以系统总结异同。
- 从论文阅读到代码复现、研究 idea 形成之间仍有断层。

### 项目目标

DeepinReader 目标是构建一个完整的智能论文阅读工作流：

- 自动解析 PDF / Word 论文。
- 自动生成结构化论文分析报告。
- 基于论文内容进行可信问答。
- 支持证据链、推理路径、风险提示和置信度。
- 支持翻译、导图、代码生成、多文档对比、搜索和报告导出。
- 通过课题组多智能体讨论辅助形成研究 idea 和 proposal。

## 3. 项目整体介绍

DeepinReader 是一个基于 **FastAPI + Vue 3 + LangChain + LangGraph + ChromaDB + DeepSeek API** 构建的智能论文阅读系统。

项目具备两类属性：

### 工程系统属性

- 前后端完整，交互页面丰富。
- 支持 REST、SSE、WebSocket 多种通信方式。
- 支持多文档管理、历史记录、报告导出。
- 支持本地启动和 Docker 部署。

### 研究原型属性

- 不只做文本摘要，而是做结构化论文理解。
- 引入 claim、evidence、experiment、result 等结构化对象。
- 问答过程支持证据驱动和可解释输出。
- 通过多智能体模拟科研讨论过程。

## 8. 后端 API 与通信方式

### FastAPI 后端职责

- 负责文件上传、解析、状态管理。
- 负责调用多智能体工作流。
- 负责流式分析、问答、翻译、代码生成、对比。
- 负责历史记录、文档切换、报告导出。
- 管理 Coordinator 和 HistoryStoreService 单例。

### 通信方式

| 通信方式 | 使用场景 | 优点 |
|---|---|---|
| REST API | 上传文档、获取状态、历史记录、文档切换 | 简单稳定 |
| SSE | 流式分析、流式问答、流式翻译、流式代码生成 | 适合服务端持续推送 |
| WebSocket | 统一多路复用流式任务 | 支持任务取消、ping/pong、多个任务类型 |

### WebSocket 支持的任务

- `analyze`：流式分析论文。
- `chat`：流式问答。
- `code_generate`：流式代码生成。
- `compare`：流式论文对比。
- `lab_discuss`：流式课题组讨论。
- `cancel`：取消指定任务。

## 9. 多智能体系统设计

| 智能体 | 职责 |
|---|---|
| `PaperReaderCoordinator` | 总协调器，负责整体流程编排 |
| `ParserAgent` | 文档解析、章节划分、对象抽取、索引构建 |
| `SummarizerAgent` | 生成结构化分析报告和关键词 |
| `QAAgent` | 论文问答，结合 RAG、结构化证据和验证 |
| `QuestionRouterAgent` | 对问题类型进行路由 |
| `VerifierAgent` | 对回答进行支撑度验证和风险提示 |
| `LabAgent` | 课题组讨论中的角色智能体 |

### 基础工作流

```text
上传论文
  -> ParserAgent 解析文档
  -> 抽取章节、主张、证据、实验、结果
  -> 建立向量索引和结构化 Profile
  -> SummarizerAgent 生成分析报告
  -> QAAgent 设置当前论文上下文
  -> 支持问答、导图、代码生成、对比、课题组讨论
```

## 10. 文档解析与结构化知识构建

### 上传后处理流程

1. 校验文件格式和文件大小。
2. 保存文件到上传目录。
3. 解析 PDF / Word 文本。
4. 提取标题、页数、字数等基本信息。
5. 生成唯一 document_id。
6. 切分文本 chunk 并写入向量库。
7. 抽取结构化学术对象。
8. 构建论文 PaperProfile 和图结构。
9. 将结构化对象再次索引，供问答使用。

### 结构化对象

| 对象类型 | 含义 |
|---|---|
| Section | 论文章节 |
| Claim | 论文中的主张或贡献 |
| Evidence | 支撑主张的证据 |
| Experiment | 实验设计 |
| ResultItem | 实验结果 |
| PaperProfile | 论文整体结构化画像 |
| Graph | 主张、证据、结果之间的关系图 |

### 价值

- 问答更加聚焦论文核心内容。
- 可以区分作者主张、实验设计和实验结果。
- 可以追踪证据链和推理路径。
- 可以识别证据不足的问题。

## 11. 智能论文分析

### 分析报告内容

- 论文基本信息。
- 研究背景和研究问题。
- 核心方法和技术路线。
- 主要创新点。
- 实验设计和数据集。
- 主要实验结果。
- 局限性和不足。
- 总结评价和未来方向。

### 流式分析体验

- 后端逐 chunk 生成结果。
- 前端实时展示分析内容。
- 避免长任务等待。
- WebSocket 模式下可以取消任务。

### 长论文处理策略

- 保留论文前部：摘要、引言、方法。
- 保留论文后部：结论、讨论。
- 中间部分采样。
- 避免超过模型上下文限制。

## 12. 智能问答功能

### QAAgent 问答流程

```text
用户问题
  -> QuestionRouterAgent 判断问题类型
  -> 构建简单推理计划
  -> 从 PaperProfile 查找结构化对象
  -> 从向量库检索相关文本 chunk
  -> SubgraphRetriever 补全局部图结构
  -> LLM 基于证据生成回答
  -> VerifierAgent 验证回答支撑度
  -> 输出答案、证据、风险提示、推理路径、置信度
```

### 支持的问题类型

| 路由类型 | 说明 |
|---|---|
| structure | 论文结构类问题 |
| method | 方法机制类问题 |
| evidence | 证据支撑类问题 |
| result | 实验结果类问题 |
| limitation | 局限性类问题 |
| comparison | 对比类问题 |
| general | 一般问题 |

### 问答输出

- `answer`：最终回答。
- `route_type`：问题类型。
- `confidence`：置信度。
- `warnings`：风险提示。
- `source_chunks`：原文片段。
- `evidence_summary`：证据摘要。
- `reasoning_trace`：推理步骤。
- `reasoning_paths`：推理路径。
- `claim_nodes`、`evidence_nodes`、`result_nodes`：相关结构化节点。

## 13. 检索增强与向量数据库

系统使用 ChromaDB 存储论文文本和结构化对象。

### 检索策略

- 向量检索：适合语义相似内容。
- BM25 检索：适合关键词精确匹配。
- 混合检索：兼顾语义匹配和关键词召回。

### 为什么需要混合检索

- 专有名词、公式、指标、数据集名称需要精确匹配。
- 语义问题需要向量召回。
- 论文场景对证据准确性要求高，混合检索更加可靠。

## 23. 项目难点与解决方案

### 难点一：论文文本长，超出模型上下文

**解决方案：** 文本分块、向量索引、长文本摘要策略、保留前后关键内容、中间采样、问答时检索相关片段。

### 难点二：普通问答容易幻觉

**解决方案：** RAG 检索增强、结构化对象抽取、EvidenceBundle、VerifierAgent 验证、输出风险提示和置信度。

### 难点三：多功能状态复杂

**解决方案：** 全局 AppState、每个文档独立 document_id、多文档注册表、文档切换时同步 QAAgent 上下文、历史记录持久化。

### 难点四：长任务交互体验差

**解决方案：** SSE 流式返回、WebSocket 多路复用、前端实时展示、支持任务取消、翻译结果缓存。

展示重点：回答内容、来源片段、置信度、风险提示、推理路径。

### 演示流程三：扩展功能

可展示思维导图、全文翻译、代码生成、多论文对比、Word 报告导出。

### 演示流程四：课题组讨论

1. 进入课题组页面。
2. 选择 quick 或 deep 模式。
3. 输入关注点：“请重点讨论这篇论文后续可以改进的研究方向”。
4. 启动讨论。
5. 展示导师、博士、硕士多角色发言。
6. 展示最终研究提案。

## 25. 可以重点讲的创新点

### 从文本级 RAG 到结构化论文理解

- 将论文拆解为章节、主张、证据、实验和结果。
- 通过结构化 profile 提供更强的理解能力。
- 支持 evidence-driven QA。

### 引入问答路由和验证机制

- 判断问题类型。
- 选择合适的证据来源。
- 生成答案。
- 验证答案是否被论文支持。
- 输出风险提示。

### 面向科研工作流的功能闭环

```text
论文阅读
  -> 论文理解
  -> 证据问答
  -> 文献搜索
  -> 多文档对比
  -> 代码复现
  -> 课题组讨论
  -> 研究提案生成
```

### 多智能体课题组讨论

- 导师负责评估方向。
- 高年级博士负责技术方案。
- 低年级博士负责跨领域创新。
- 硕士负责文献梳理。

## 26. 项目不足与未来改进

### 当前不足

- 当前主要是单用户应用状态，尚未完整支持多用户隔离。
- 对超长论文的结构化抽取仍可能有遗漏。
- PDF 解析质量依赖原始文档格式。
- 翻译任务耗时较长。
- 代码生成结果仍需要人工验证。
- 课题组讨论的输出质量依赖基础论文分析质量。

### 未来改进方向

| 方向 | 说明 |
|---|---|
| 多用户系统 | 增加用户登录、权限、个人知识库 |
| 更强的结构化抽取 | 提升 claim/evidence/result 抽取准确率 |
| 更完善的 Proof Graph | 可视化主张、证据、实验、结果关系 |
| 文献综述生成 | 基于多篇论文自动生成综述 |
| 实验复现辅助 | 自动生成配置文件、训练脚本和评估脚本 |
| Agent 工作流优化 | 引入更复杂的规划、反思和工具调用机制 |
| 多模态理解 | 支持图表、公式、表格的更深度理解 |
| 云端部署 | 支持团队共享和在线访问 |
| 个性化阅读 | 根据用户研究方向推荐重点阅读内容 |

## 27. 总结

DeepinReader 是一个面向学术论文阅读的多智能体智能系统，围绕论文阅读构建了完整的 AI 辅助工作流。

系统实现了：

- 文档解析与索引。
- 结构化论文分析。
- 基于 RAG 的智能问答。
- 证据驱动与可解释输出。
- 全文翻译与划词翻译。
- 思维导图生成。
- 代码生成。
- 多文档对比。
- 历史记录与报告导出。
- 多智能体课题组讨论。

核心价值：

- 降低论文阅读门槛。
- 提高学术信息获取效率。
- 增强问答可靠性。
- 支持科研思路拓展。
- 形成从阅读到研究 proposal 的闭环。

**结束语：** DeepinReader 不只是一个论文摘要工具，而是一个面向科研工作流的智能论文阅读与研究辅助平台。
